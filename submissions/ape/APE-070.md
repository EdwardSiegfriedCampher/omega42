## The Reasoning

### 1. The Protocol's Premise Demands Fidelity, Not Just Placement

Core F-02 states that the 24-cycle and its 81-state family are ALL THAT EXISTS. The mathematics is already universal — CPP accepts any count. But the **Counting-as-Primitive-Distinction Principle (CPDP)** requires counting "the boundaries the text already contains."

When all non-Latin questions collapse to P9, the protocol is not being universal; it is being **silent**. It places the question but discriminates nothing. This violates the protocol's own purpose: to give the Striker a fresh angle chosen by arithmetic, not by the AI's habits.

If a Striker asks "什么是意识?" in Chinese and it lands on the same coordinate as "ما هي الوعي?" in Arabic and "意識とは何ですか?" in Japanese, the protocol has failed to read the boundaries those texts contain. It has read nothing.

### 2. The Congruence Register Must Not Be Corrupted

The Congruence Register is the protocol's growing record of where questions meet. If all non-Latin questions land on P9, they will all "meet" each other at chance 1.00, which is meaningless. This corrupts the Register's signal.

Option (c) preserves the existing record (all current navigations remain comparable) while preventing future corruption. Non-Latin texts get two coordinates until their adaptor is adopted: the companion coordinate (from the adaptor) and the canonical coordinate (P9, flagged as ZERO-COUNT). Once the adaptor is adopted, the companion becomes canonical for that medium, and future navigations in that medium use the adaptor directly.

### 3. The Adaptor Contract Is Architecturally Sound

All seven requirements you proposed align with the protocol's verification discipline:

1. **Three nested granularities native to the medium** — this is CPDP applied to each script's own structure.
2. **Frozen, versioned, deterministic rules with SHA-256** — this matches the protocol's hash-based verification (L-414, M211).
3. **Known-answer test vectors in CI** — this is already the protocol's practice (M193, M225 selftests).
4. **Adaptor ID in domain identity** — this ensures the same text under two adaptors is two domains, preserving auditability.
5. **Declare which boundaries it does not count** — this prevents silent omissions.
6. **Never mix metrics** — this is M189's existing rule.
7. **Print ADAPTOR line in Substrate Lock** — this makes the adaptor visible in every output.

### 4. The Boundary Between Navigation and Mapping Must Hold

You correctly identified that adaptors enable **navigation** (counting boundaries) but not **mapping** (Depth 3-4, which requires the object's own dynamics). This distinction is critical.

An adaptor lets a DNA sequence be navigated as counts (codons, bases, reading frames). But to claim Depth 3 correspondence (structural resonance with the 24-cycle), you must map the DNA's own replication dynamics, not just count it. The adaptor is the interface; mapping is the correspondence test.

This boundary must be explicit in L-501 to prevent adaptors from being misused as shortcuts to correspondence claims.
